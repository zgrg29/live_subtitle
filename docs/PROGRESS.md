## 质量现状（诚实版）

用 60 句评测集（`eval/mt_eval.jsonl`，5 类各 12 句）量的，不是挑例子：

| 指标 | 裸模型 | + 文本层 |
|---|---|---|
| F1（60 句书写体） | 0.354 | **0.610** |
| 明显错（书写体） | 24 / 60 | **5 / 60** |
| F1（60 句无标点，≈ASR 输出） | 0.273 | **0.504** |
| 明显错（无标点） | 28 / 60 | **10 / 60** |
| **F1（37 句 VTuber holdout）** | 0.180 | **0.259** |
| 明显错（VTuber holdout） | 24 / 37 | **17 / 37** |
| p50 延迟 | 71ms | 75ms |

⚠️ **别再引用 0.605 作为「翻译质量」**。那是书写体 + 我们自己出题/调词，双重乐观偏差。
真实可用性看 VTuber 那一行：**一半句子能看懂，另一半要猜**。

2026-10-21 词典扩容后的回归（`tools/eval_mt.py --tag ja-glossary2`）见 `logs/eval/`：
F1 从 0.603 升到 **0.610**，「明显错」仍是 5/60，没有回退。
新增词条只加「实测会翻错」或「说法固定」的，
**加词不再以提分为目标**，只保证 60 句回归不降。

`eval/holdout_vtuber.jsonl` 是冻结的 holdout——**禁止拿它调词典**，否则就失去意义。
要调词请用 `eval/dev_vtuber.jsonl`。

修好的主要是**词汇层**：

| 例子 | 过去 | 现在 |
|---|---|---|
| こんばんは | 晚安 | 晚上好 |
| おつかれさまでした | 我抓住了你 | 辛苦了 |
| マイクの音量 | 迈克的音量好吗 | 麦克风的音量好吗 |
| 配信を始めます | 开始发送 | 开始直播 |
| スパチャ | spacha | 超级留言 |
| 原神のイベント | 神迹活动 | 原神活动 |

**还会错的（全是语法/语气，词典救不了）**：

| 例子 | 输出 | 问题 |
|---|---|---|
| とりあえずセーブしておきます。 | 先来保存一下 | 意思对，「存个档」更地道 |
| 見に来てくれて、本当にありがとうございました。 | 你真的来找我，我真的是谢谢你 | `〜てくれて` 理解错 |
| えーと、今日はちょっと調子が悪いので… | 嗯，今天事情有点不对… | 长句语气整体走形 |
| 音が割れてるので、音量下げます | 噪音有点破，所以音量会降低 | 割れる / 主动被动 |
| 視聴者参加型でやります | 以后，观众可以参加 | 复合名词 |

结论：**日常口语 + 专有名词现在可读；长句的语气和逻辑连接仍是 75M 的天花板**。

## 词典扩容说明

固定表达从 137 条扩到 **292** 条，术语从 88 条扩到 **155** 条。原则：

1. **固定表达只收「整句说完」的句子**：寒暄、开播/收播、观众互动、游戏实况的固定反应、
   配信トラブル、告知。整句表是精确匹配，命中才生效，风险最低。
2. **术语收「句中出现也会错」的词**：平台功能、VTuber 圈用语、游戏系统与游戏名、食物名。
   `pre`（译前替换）适合片假名专名；`post`（译后修错）适合「句子结构对、只有这个词错」。
3. **去重**：原文件有 8 组重复（なるほど、たしかに、うける、しんどい、だるい、ねむい、
   おなかすいた、おつかれ），已合并；修掉 `のどかわいた` 拼写（应为 `のどがかわいた`）。
4. **不追求覆盖率**：短语表只兜「每次说法都一样」的句子；主播随口的长句靠模型 + 术语，
   加更多短语不会让长句变好。继续加词前先看 `docs/DEVLOG.md` 的评测结论。

## 已知局限（开发视角）

1. **断句合并是启发式，不是语义理解**。靠日语句尾（助词、接续词、`です/ます`、长度）判断
   「像不像说完了」：以名词结尾的长片段、`舞い` 这种动词中顿、停顿超过 800ms 的换气，
   仍可能被切成两行。反过来，两句独立的话如果间隔不到 800ms，也可能被并成一行。
2. **长句的语气和逻辑连接**。`〜てくれて`、`〜ておく`、`えーと` 开头的长句，75M 模型只能
   译到「意思大致对、语气不对」。这是模型能力上限，词典救不了。
3. **词典覆盖不到的词仍会错**。`のり弁当` 已加；但新的食物名、地名、作品名还会错。
4. **偶发粤语**。极少数句子会输出「我哋…」，是翻译模型训练语料混杂导致的。
5. **只认一个人说话**。多人抢话时会把声音混在一起识别。
6. **听不懂游戏里的语音**。只采集麦克风（ADR-001），日服队友语音不在范围内。
7. **低配机器的延迟**。4 核 N97 短句 0.8–1.2 秒；更弱的机器更慢，可调 `vad.end_silence_ms`、
   `segment.merge_wait_ms`，或 `segment.merge = false` 换速度。
8. **不翻译歌词**。歌词的比喻和韵律不是 75M 模型能处理的，硬翻只会更难听。
