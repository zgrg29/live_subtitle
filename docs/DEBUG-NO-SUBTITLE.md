# 「字幕が出ない」の切り分け（0.5.1 以降）

> 0.5.0 で「レベルメーターは動くのに字幕がまったく出ない」という報告を受けて書いた手順書。
> 開発機では再現しない前提で、**ユーザーの画面だけで原因を特定する**ためのもの。

## 1. まず、報告から分かること

報告に添えられた設定ページのスクリーンショットには、次の状態が写っていた。

| 観測 | 意味 |
|---|---|
| 入力レベル **-28 dB**、緑の「発話を検出」 | 音声はパイプラインに届いている（フレームが流れている） |
| 動作中のデバイス **In 1-2 (MOTU M Series) (2ch)** | 2ch のオーディオインターフェースを使っている |
| 入力ゲイン **3.8×**、認識しきい値 **-65 dB** | 「出ないから感度を上げた」という後付けの操作。原因ではない |
| 「昨日のは出てた」= 0.4.0 では動いていた | 0.5.0 の変更（自動消去 / デバイス選択 / ゲイン・しきい値 / 自動で設定ページ）が疑わしい |

レベルメーターは **pipeline スレッドが実際に受け取ったフレーム**から作っている
（`pipeline._publish_level`）。つまりメーターが動いている時点で、

```
マイク → フレーム受信 → VAD 判定 →（ここまで生存）→ 切句 → ASR → composer → WS → 字幕ページ
```

の **VAD より後ろ**のどこかで止まっている。切り分けるべきは 4 つだけ：

1. ASR が空文字を返している（音声が声でない / チャンネル違い / モデル不調）
2. 切句・統合が永久に待っている（0.4.0 と同じロジックなので可能性は低い）
3. 字幕は生成されているが WS で届いていない
4. 届いているが OBS が表示していない（URL・キャッシュ・シーン）

## 2. 0.5.1 で追加した「証拠」

| 追加物 | 何が分かる |
|---|---|
| `/api/diag` | 段ごとのカウンタ（frames / speech_frames / utterances / asr_calls / **asr_empty** / emitted）、接続数、チャンネル別レベル、しきい値 |
| 設定ページ「診断」タブ | 上を ✓ / ! / ✕ で表示。**一番下に「判定」を 1 行**で出す |
| 「直近6秒で認識テスト」 | pipeline が実際に受けた音声を ASR に通し直す。ここで文字が出るかで「音声側」か「表示側」かが確定する。WAV も `logs/` に保存 |
| 「サポート用ファイルを保存」 | `diag.json` + `summary.txt` + `config.toml` + 直近10秒 `recent-10s.wav` + ログ末尾を zip にまとめる（外部送信なし） |
| 入力チャンネル（音声タブ） | 2ch インターフェースで「入力2」を選べる。ch 別レベルも表示 |
| `asr_empty` カウンタ | **今まで完全に無音だった失敗**。ASR が空を返しても `metrics` には何も残らなかった |

### 判定の読み方

| 判定（`_diag_verdict`） | 原因 | 直し方 |
|---|---|---|
| 音声が届いていません | デバイスが抜けた / 他アプリが占有 / 5 秒以上無音 | デバイス再選択、他アプリを閉じる |
| VAD が声を検出していません | ミュート、しきい値が高い、ゲイン不足 | 音声タブで調整 |
| 文の区切りができていません | VAD は反応するが `min_speech_ms` 未満しか続かない | ゲイン / しきい値 |
| **認識結果が空です** | **入力チャンネル違い**、音楽・ノイズ、モデル不調 | 入力チャンネルを 2 / ミックスに。認識テストの WAV を聴く |
| 字幕として配信されていません | 統合待ち / 翻訳で例外 | ログの `last_error` |
| OBS の字幕ページが接続していません | URL のポート違い、OBS のキャッシュ | URL 確認 → キャッシュ削除して再読み込み |
| 正常に動いています | — | 表示側（シーン / フィルタ / 音声モニタ）を疑う |

## 3. 今回の本命：2ch インターフェースの入力チャンネル

0.5.0 までは `MicSource` が **常に 1ch でデバイスを開き、`indata[:, 0]` だけ**を見ていた。
MOTU / UR22 / AG03 のような 2ch インターフェースでマイクを **入力2** に挿していると、

- 1ch 目には**かすかな回り込み**だけが入る（レベルは -40 dB 前後で動く）
- VAD はしきい値を下げれば反応する
- ASR に渡るのは声ではないので、**空文字**が返る
- 空文字は `composer` が静かに捨てるので、**画面には何も出ない**

ゲイン 3.8×・しきい値 -65 dB というスクリーンショットの値は、この状態を
「音量の問題」と誤診して上限まで上げた形と一致する。

0.5.1 では `audio.channel`（0 始まり、`-1` = 全 ch ミックス）を追加し、
音声タブから選べるようにした。デフォルトは `0`（従来と同じ）なので、
既存ユーザーの音声経路は変わらない。

## 4. ユーザーに送る手順（日本語テンプレ）

### 4-1. まず証拠を取る

```
お手数ですが、設定ページの「診断」タブを開いて、上から 2 枚スクリーンショットを送ってもらえますか？
（http://127.0.0.1:8765/admin?tab=diag でも開けます）

1. 「診断」タブ全体（✓／✕ と一番下の「判定」）
2. 「直近6秒で認識テスト」を押した後の結果
```

### 4-2. 判定別の返信

- **認識テストで文字が出ない** →
  「2ch のオーディオインターフェースで、マイクが入力2に挿さっていると、
   これまでの版は入力1だけを見ていました。設定ページ →「音声」→ 入力チャンネルを
   **2** か **すべてミックス** に変えて、「保存して適用」してみてください。」
- **文字は出るのに OBS に出ない** →
  「OBS のブラウザソースの URL が `http://127.0.0.1:8765/overlay` になっているか、
   右クリック →「キャッシュをクリアして再読み込み」を試してください。」
- **それでも直らない** →
  「「診断」タブの『サポート用ファイルを保存』で zip を保存して送ってください。
   設定と直近10秒の音声が入っています（外部送信はしません）。」

## 5. ローカルで再現・検証する

```powershell
# 1) 単体テスト（チャンネル選択・空認識の可視化・判定ロジックを含む 84 件）
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

# 2) 2ch デバイスの代わりに、ダミーの sounddevice で ch2 選択を検証
.\.venv\Scripts\python.exe -m unittest tests.test_audio_settings.MicChannelSelectionTest -v

# 3) 実機（マイクあり）で診断ページを確認
.\.venv\Scripts\python.exe -m livesub run --port 8801 --no-browser
#   → http://127.0.0.1:8801/admin?tab=diag

# 4) 合成音声だけで API を確認（マイク不要）
.\.venv\Scripts\python.exe -m livesub run --synthetic 12 --port 8799 --no-browser
curl http://127.0.0.1:8799/api/diag
```

`_diag_verdict` の分岐は `tests/test_audio_settings.py::DiagVerdictTest` に固定してある。
判定文言を変えるときはテストも一緒に直す。

## 6. 今回やらないこと（誤診を避ける）

- **0.4.0 に戻させる**：原因が分からず、同じ報告が再発するだけ。
- **モデルや辞書を疑う**：認識結果が空なのに辞書をいじっても何も変わらない。
  まず「直近6秒で認識テスト」で文字が出るかを見る。
- **`threshold` をさらに下げる**：しきい値は VAD の入口だけ。ASR が空を返す原因にはならない。
- **録音をオンにさせる**：診断 zip に直近10秒の WAV が入るので、わざわざ録音を有効化しなくてよい。
