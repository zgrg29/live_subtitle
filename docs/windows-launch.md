# Windows での起動方法（システムにブロックされた場合）

検証機（Windows 11・スマート アプリ コントロール有効）での実測結果：

| ファイルの種類 | 結果 |
|---|---|
| `.exe`（未署名） | **実行できる**。「不明な発行元」が 1 回出るので「詳細情報 → 実行」を選ぶ |
| `.bat` / `.cmd` | **スマート アプリ コントロール**に直接拒否される。回避手段はない |
| `.lnk` / `.ps1` | 「危険なファイルの種類」ポリシーで拒否される（Dangerous file extension from the web） |

そのため、このプロジェクトの入口は **exe** です。スクリプトのランチャーは使いません。

## 推奨：exe をダブルクリック

```
LiveSub.exe
```

1. 初回は「不明な発行元」と出る →「詳細情報」→「実行」
2. 黒いコンソールウィンドウが開く。**閉じると字幕が止まります**
3. ブラウザで <http://127.0.0.1:8765/overlay> を開いて確認
4. OBS に「ブラウザ」ソースを追加し、同じ URL を指定

ポータブル版はフォルダごとコピーできます：`LiveSub.exe` + `_internal\` + `models\` + `config.toml`。

## 代替：コマンドライン（exe がブロックされた場合）

ごく一部のマシンではスマート アプリ コントロールが強制モードで、exe も拒否されます。
その場合は `Win + R` から次を実行してください：

```
D:\live_subtitle\.venv\Scripts\python.exe -m livesub run
```

（ソース環境が必要です。README の「B. ソースから動かす」を参照。）

## スクリプトがブロックされる理由

ウイルス対策の誤検知ではなく、プログラムの中身とも関係ありません。
Windows は `.bat` / `.lnk` / `.ps1` / `.vbs` のような「実行可能なスクリプト／ショートカット」を
既定で信頼せず、「実行する」という選択肢も出しません。exe は別の判定経路で、
未署名なら 1 回だけ確認を出し、ユーザーが自分で決められます。

## 長期的な解決策：コード署名

署名すれば「不明な発行元」も出なくなります。配信者向けの最終形はこれです：

| 方法 | コスト | 補足 |
|---|---|---|
| OV コード署名証明書 | 有料（年額） | SmartScreen とスマート アプリ コントロールの両方が通る。最も直接的 |
| Microsoft Store（MSIX） | 開発者アカウント＋審査 | ストアが署名するが、更新がストアの都合に縛られる |
| 未署名のまま | 0 | 初回起動のたびに確認が必要。強制ポリシーのマシンでは拒否される |

## この PC の状態を確認する

```powershell
# スマート アプリ コントロール：0=オフ 1=オン 2=評価モード
(Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\CI\Policy').VerifiedAndReputablePolicyState
```

ブロックの詳細ログ：イベント ビューアー → `アプリケーションとサービス ログ → Microsoft → Windows → CodeIntegrity → Operational`。
