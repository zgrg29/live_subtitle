# LiveSub

OBS 用の**ローカル・リアルタイム日本語→中国語字幕**です。
マイクの音だけを拾い、ゲーム音には触れず、音声を外部へ送信しません。**すべてオフライン**で動きます。

> **バージョン 0.4.0**
> 日本語音声を認識して中国語字幕を作り、OBS のブラウザソースに表示します。
> 設定はブラウザの設定ページ `http://127.0.0.1:8765/admin` から変更でき、
> 辞書の追加も**再起動なし**で反映されます。
> 言い切れていない文は語尾を見て保留し、続きと統合してから翻訳します
> （「このゲーム、」「けっこう難しいんですよね」を 2 行に割らないため）。

**対象**：日本語で**雑談**・**ゲーム実況**をする配信者と、その中国語圏の視聴者。
**歌枠・歌詞は対象外**です。歌詞の比喩や韻律は 75M の翻訳モデルでは扱えず、無理に翻訳すると
かえって読みにくくなるため、意図的に切り捨てています。

> 翻訳品質について正直に言うと、**日常会話・挨拶・固有名詞は読めます**が、
> **長い口語のニュアンスは半分ほど推測**になります。評価データと今後の予定は
> 開発者向けドキュメント（中国語）の [docs/PROGRESS.md](docs/PROGRESS.md) にまとめています。

## 動作環境

- Windows 10 / 11（64bit）
- CPU 4 コア程度（GPU 不要）
- メモリ 4GB 以上（実行時の追加使用量は約 350MB）
- OBS Studio 28 以降を推奨
- ポータブル版は**インターネット不要**（モデル同梱）。ソース版は初回のみモデル取得が必要

## クイックスタート

### A. ポータブル版（Python 不要・推奨）

1. [Releases](https://github.com/zgrg29/live_subtitle/releases) から `LiveSub-0.4.0-win64.zip` を取得
2. 任意のフォルダに解凍（パスに日本語や中国語を含めないほうが安定します）
3. `LiveSub.exe` をダブルクリック
4. 初回に「不明な発行元」と表示されたら **詳細情報 → 実行**（コード署名をしていないため）
5. 黒いウィンドウが開きます。**閉じると字幕が止まります**
6. ブラウザで <http://127.0.0.1:8765/admin> を開いて設定

フォルダの中身：

```
LiveSub.exe           起動する
使い方.txt            この内容の簡易版
config.toml           設定（フォント・色・マイクなど）
models\               認識モデルと翻訳モデル
_internal\            ランタイムと内蔵辞書（触らない）
```

- フォント・色・マイクを変える：**設定ページ**（推奨）か、同じフォルダの `config.toml` を編集して再起動
- 辞書を追加する：**設定ページの「辞書」タブ**（即時反映）を使うのが簡単です。
  パネルから保存すると、同じフォルダに `glossary\`（TSV）が作られ、次回から内蔵辞書を上書きします
- フォルダごと圧縮して配布できます（モデル込みで 600MB 前後）

### B. ソースから動かす（開発用）

#### 0. 環境

- Windows 10 / 11
- Python 3.10 〜 3.13（3.11 / 3.12 が無難）

#### 1. インストール

```powershell
git clone https://github.com/zgrg29/live_subtitle.git
cd live_subtitle
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e .
```

#### 2. 日本語認識モデルを取得（約 153MB・初回のみ）

```powershell
python -m livesub download --repo csukuangfj/reazonspeech-k2-v2 --to models/sherpa-ja
```

この手順を飛ばしても起動はできますが、**デモモード**（台本のテキスト）になります。
起動時のウィンドウにその旨が表示されます。

#### 3. マイクなしで自己テスト

```powershell
python -m livesub selftest                          # デモエンジンで経路を確認
python -m livesub selftest --wav your.wav --real    # 実モデルで音声ファイルを処理
```

次のような出力が出れば、経路と計測が動いています：

```
idx    audio s   asr ms   mt ms   end->line ms  text
────────────────────────────────────────────────────────────
2         5.41   1637.9   418.5       1736.1  ヤンバルクイナとの出会いは十八歳の時だった  [統合 2 断片]
                                              → 与Yambarquina的相遇是在18岁的时候。
```

`[統合 2 断片]` は、いったん区切られた文が統合されたことを表します。`idx` は最後の断片の番号なので
連番にならないことがあります。ASR / MT の時間は実測値です（OBS の描画は含みません）。

#### 4. 起動

いちばん確実な方法（`.bat` に依存しません）：

1. `Win + R` を押す
2. 次を貼り付けて Enter

```
D:\live_subtitle\.venv\Scripts\python.exe -m livesub run
```

3. 黒いウィンドウが出れば起動成功です。**閉じると字幕が止まります**
4. <http://127.0.0.1:8765/overlay?preview=1> をブラウザで開くと、配信なしで見た目を確認できます
   （`?debug=1` を付けると接続状態と遅延を表示）

> Windows 11 の「スマート アプリ コントロール」は `.bat` / `.lnk` をブロックすることがあります。
> ダブルクリックで起動できないときは [docs/windows-launch.md](docs/windows-launch.md)（日本語）を参照してください。

## OBS への追加

1. OBS の **ソース** パネル → **`+`** → **ブラウザ**
2. 名前は任意（例：`字幕`）
3. プロパティに次を入力

| 項目 | 値 |
|---|---|
| URL | `http://127.0.0.1:8765/overlay` |
| 幅 | `1920` |
| 高さ | `1080` |

4. **「ソースが非表示のときにシャットダウン」はオフ**（オンにするとシーン切替のたびに再読み込みされ、字幕がちらつきます）
5. 「シーンがアクティブになったときにブラウザを更新」もオフ
6. カスタム CSS は空欄（スタイルは LiveSub 側で設定）
7. ソースを右クリック → **変換** → **画面に合わせる**（または位置を `0, 0` に）

背景は最初から透明です。クロマキーやブレンドモードの設定は不要です。
詳しい手順は [docs/obs-setup.md](docs/obs-setup.md)（日本語）にあります。

## 設定ページ

起動後、ブラウザで次を開きます：

```
http://127.0.0.1:8765/admin
```

左が **1920×1080 のリアルタイムプレビュー**、右が設定です。変更するとプレビューがすぐ変わり、
「保存して適用」で **OBS 側の字幕にも即時反映**されます（OBS の再読み込みは不要）。

**スタイル**タブで変えられるもの：

| 項目 | 内容 |
|---|---|
| フォント | インストール済みのフォント名。カンマ区切りで複数指定可 |
| 文字サイズ | 中国語・日本語を別々に調整 |
| 文字色 | 中国語・日本語を別々に指定 |
| 縁取り | オン／オフ＋色＋太さ（オフで縁取りなし） |
| 背景 | 半透明の長方形。色と透明度を指定（黒＋透明度で黒帯） |
| 表示位置 | 下／上、端からの距離（%） |
| 行数 | 同時に表示する行数 |
| 二言語 | 日本語の原文を表示するか |

**辞書**タブ：

- **定型フレーズ（文全体）**：文全体が一致したときだけ有効。例 `こんばんは` → `晚上好`
- **用語**：2 つのモード
  - `pre`：翻訳前に日本語の語を中国語へ置き換えてからモデルに渡す（カタカナの固有名詞・ゲーム名・食べ物）
  - `post`：通常どおり翻訳し、訳文の「誤訳パターン」を正しい語へ置換（原文にその語があるときだけ有効）
- **試し翻訳**：1 文をその場で翻訳して、追加した語が効いているか確認できます
- **保存して即時反映**：再起動なしで反映

> パネルから保存すると、プログラムのフォルダに `glossary\`（UTF-8・Tab 区切りのテキスト）が作られ、
> 内蔵の辞書を上書きします。内蔵版に戻したいときは、そのフォルダを削除して再起動してください。

## 辞書を手で編集する

辞書はテキストです。**Tab 区切り・UTF-8** で保存してください。

ユーザー辞書の場所は、ソース版が `glossary/`、ポータブル版が `LiveSub.exe` と同じフォルダの
`glossary\` です（初回に設定ページから保存すると作られます）。
`_internal\glossary` は内蔵辞書なので編集しないでください。

**`phrases.tsv`** — 定型フレーズ（文全体が一致したときだけ、モデルを通さずに表示）：

```
こんばんは	晚上好	夜の挨拶
```

**`terms.tsv`** — 用語。列は `日本語 <TAB> 中国語 <TAB> モード <TAB> 誤訳パターン <TAB> メモ`：

```
配信	直播	post	发送|发货	配信は「送信」ではない
スパチャ	超级留言	pre		投げ銭
```

| モード | 動作 | 向いているもの |
|---|---|---|
| `pre` | 翻訳前に日本語の語を中国語へ置換してからモデルへ渡す | カタカナの固有名詞・ゲーム名・食べ物名（モデルは注入した中国語をそのまま残します） |
| `post` | 通常どおり翻訳し、訳文の誤訳パターンを置換 | 文の構造は合っていて、その語だけ違う場合（例：`配信` → 「发送」）。誤訳パターンは `\|` 区切りで複数指定可 |

編集したら再起動してください（設定ページから保存した場合は再起動不要）。
**実際に誤訳を確認した語だけを追加**し、追加後は `python tools/eval_mt.py` で 60 句の回帰を確認するのが
このリポジトリのルールです（[docs/PROGRESS.md](docs/PROGRESS.md)）。

## config.toml

初回起動時に、日本語コメント付きの `config.toml` が自動生成されます。
設定ページで保存した項目は再起動不要ですが、**ファイルを直接編集した場合は再起動**が必要です。
主な項目：

| 項目 | 既定値 | 説明 |
|---|---|---|
| `overlay.bilingual` | `true` | 日本語の原文も表示する |
| `overlay.font_family` | Microsoft YaHei ほか | インストール済みのフォント名 |
| `overlay.zh_size` / `ja_size` | `56` / `30`（`config.example.toml` は `48` / `26`） | 1920 幅基準。他の解像度では自動で拡大縮小 |
| `overlay.zh_color` / `ja_color` | `#FFFFFF` / `#B9C6D4` | 文字色 |
| `overlay.outline_color` / `outline_width` | 黒 / `5` | 縁取り。`0` でなし |
| `overlay.background` | `transparent` | `rgba(0,0,0,.35)` で半透明の背景 |
| `overlay.position` | `bottom` | `bottom` / `top` |
| `overlay.margin_percent` | `8` | 端からの距離（%） |
| `overlay.max_lines` | `2` | 同時に表示する行数 |
| `audio.device` | 空 | 空＝既定のマイク。デバイス名の一部でも可 |
| `vad.end_silence_ms` | `320` | 無音が何 ms 続いたら発話終了とみなすか |
| `segment.merge` | `true` | 半文の統合。オフで「無音が来たらすぐ表示」 |
| `segment.merge_wait_ms` | `800` | 続きを待つ最大時間 |
| `segment.max_merge` | `2` | 最大統合数 |
| `glossary.enabled` | `true` | 辞書のオン／オフ |
| `glossary.dir` | `glossary` | 辞書フォルダ |

`config.example.toml` も同梱しています（コメントは日本語）。

## しくみ

```
マイク ──20ms フレーム──► エネルギーVAD ──► 区切り ──► 文全体を認識 ──► 統合判定 ──► 翻訳 ──► WebSocket ──► OBS ブラウザソース
                                                        │（言い終わっていなければ保留し、続きが来たら再認識）
                                                        └─ 1 文ごとに記録：音声長／認識時間／翻訳時間／発話終了→表示
```

**マイクだけを拾う理由**：ゲーム音・BGM・通話が混ざらないので、小さいモデルでも認識率が上がり、
音声分離も大モデルも不要になります。そのぶん「ゲーム内のボイス」は拾えませんが、
これは「低コストで箱から出してすぐ使える」こととの引き換えです（設計判断は
[DECISIONS.md](DECISIONS.md) ADR-001、中国語）。

**文全体を認識する理由**：マイク入力ではストリーミング認識と体感がほとんど変わらず、
文全体のほうが精度が高く、コードもモデル選定も単純になります（[ARCHITECTURE.md](ARCHITECTURE.md)、中国語）。

## 遅延とリソース

遅延はすべて実測タイムスタンプに基づきます。

| 段階 | 実測 | 補足 |
|---|---|---|
| 発話終了 → 区切り判定（無音待ち） | **320ms** | 設定可。遅延の大きな部分 |
| 半文の統合待ち | **0–800ms** | 「言い終わっていない」と判定された文だけ待つ |
| 認識（文全体・2 スレッド int8） | **140–380ms** | 2.4 秒の音声で約 200ms |
| 翻訳（opus-mt-ja-zh 75M・ONNX int8） | **45–100ms** | KV キャッシュ付きの貪欲デコード |
| 辞書（定型フレーズ） | **0ms** | テキスト照合のみ。当たればモデルを動かさない |
| 表示 → モニター | 30–80ms | OBS の描画。プログラム側の数値には含まない |

**短い文（2〜4 秒）で、発話終了から表示まで p50 約 0.8〜1.2 秒**（4 コアのマシン）。
6〜14 秒の長い音声では p50 1.2〜1.9 秒になります。

リソース（CPU のみ・GPU なし）：

- 常駐メモリ約 150MB。モデル読み込み後は +200MB 程度
- 認識は 2 スレッド（**3〜4 に増やすと遅くなることがあります**）。翻訳は設定値に従う
- GPU は既定で使いません（使う場合も配信優先で自動的に降格する設計。ADR-004）

## 既知の制限

これは「今はできない」ことで、不具合ではありません。

1. **区切りは意味理解ではなくヒューリスティック**。語尾（助詞・接続詞・`です/ます`・長さ）で
   「言い終わったか」を判断します。名詞で終わる長い断片、`舞い` のような動詞の中止、
   800ms を超える息継ぎでは、まだ 2 行に割れることがあります。逆に、本来別々の 2 文が
   800ms 以内に続くと 1 行に統合されることもあります。`segment.merge_wait_ms` と
   `segment.merge` で調整できます。
2. **長い文の語気・論理接続**。`〜てくれて`、`〜ておく`、`えーと` で始まる長い文は、
   75M モデルでは「意味はだいたい合うが語気が違う」ところまでです。モデルの能力上限で、
   辞書では直せません。
3. **辞書にない語は間違えます**。`配信`、`マイク`、`スパチャ` などは用語集で直していますが、
   新しい食べ物名・地名・作品名はまだ不安定です。
4. **まれに広東語が混ざります**。翻訳モデルの学習データ由来で、ごく一部の文が「我哋…」の
   ようになることがあります。
5. **話者は 1 人だけ**。話者分離はしません。複数人が同時に話すと混ざります。
6. **ゲーム内のボイスは拾いません**。マイクのみ（ADR-001）。日服のフレンドの音声は対象外です。
7. **低スペック PC では遅くなります**。4 コア（N97 など）で 0.8〜1.2 秒。統合待ちで最大 800ms
   増えることがあります。`vad.end_silence_ms`、`segment.merge_wait_ms`、`segment.merge = false`
   で速度を優先できます。
8. **歌詞は翻訳しません**。対象は**雑談＋ゲーム実況**です。歌枠は想定していません。

## よくある質問

**字幕ページが真っ白**
まず `http://127.0.0.1:8765/overlay?preview=1` を開いてください。プレビューが出るなら
データが届いていません。`?debug=1` で WebSocket の状態を確認できます。

**「（日本語音声 x.x 秒・認識モデル未読込）」と表示される**
デモモードです。モデルが入っていません。`python -m livesub doctor` の案内に従って
モデルを配置してください（ポータブル版は `models\sherpa-ja` を確認）。

**モデルのダウンロードが進まない**
Hugging Face への接続が不安定な場合はミラーを指定できます：

```powershell
$env:LIVESUB_HF_MIRROR="https://hf-mirror.com"
python -m livesub download --search "zipformer ja"
```

**ポートが使用中と言われる**
`python -m livesub run --port 9000` で起動し、OBS の URL も `9000` に変更してください。
すでに LiveSub が起動していないかも確認してください。

**食べ物名・固有名詞の認識や翻訳が違う**
字幕ページの日本語原文（`overlay.bilingual = true`）を見て、次の 3 つに分けてください：

- **日本語原文が違う**（`のり弁当` → `のりべん` / `乗り弁当`）：認識層の問題。同音・近音の置換や
  より大きい認識モデルが必要です。
- **日本語原文は合っていて中国語が違う**（`のり弁当` → 「海苔盒饭」など）：翻訳層の問題。
  用語集の `post` で直すのが最も安価です。
- **両方合っているのに意味が違う**：翻訳モデルの能力限界。辞書では直せません。

**ウイルスと判定される**
コード署名をしていないため、初回に「不明な発行元」と出ます。ソースから実行する場合は出ません。

**`起動.bat` が「スマート アプリ コントロール」でブロックされる**
Windows 11 のポリシーによるもので、プログラム自体の問題ではありません。
`Win + R` から次を実行してください（[docs/windows-launch.md](docs/windows-launch.md)、日本語）：

```
D:\live_subtitle\.venv\Scripts\python.exe -m livesub run
```

**OBS で字幕がちらつく / 消える**
ブラウザソースの「ソースが非表示のときにシャットダウン」をオフにしてください。
シーン切替のたびに再読み込みされると、字幕が一瞬消えます。
